# Ortho Monitoring AI

A SaaS platform for remote orthodontic and clear-aligner monitoring. It has three surfaces:

| Surface | Stack | Path |
|---|---|---|
| Clinic workspace (orthodontists, treatment coordinators, front desk) and super admin console | React 18 · Vite · Tailwind (Meridian design system) | `web/` |
| API, AI provider router, scheduling engines | Node 22 · Express · SQLite (`node:sqlite`) · TypeScript | `server/` |
| Patient app | Kotlin · Jetpack Compose · CameraX · WorkManager | `android/` |

**Product thesis:** every guided check-in ends in a clear doctor decision (*Go*, *Hold*, *Retake* or *Visit*). The
platform explains appointment timing and chair time, and the orthodontist can change both.

> **Clinical boundary.** AI output consists of *observations for clinician review*, marked "possible" or "cannot
> assess from this photo" with a visible uncertainty level. It is not a diagnostic device. Phone photos cannot confirm
> IPR or rule out a debonded attachment. No accuracy figures are shown, because none have been measured and validated
> (see the evaluation workspace).

The full product specification is in [`docs/SPECIFICATION.md`](docs/SPECIFICATION.md). It covers user journeys, screen
map, data model, API, AI architecture, image comparison, appointment rules, security, subscriptions and the phased plan.

## Quick start

Requirements: Node 22+ (it uses the built-in `node:sqlite`).

```bash
npm run setup          # installs server + web dependencies
npm run seed           # creates the demo database (2 clinics, 20+ patients, synthetic images)
npm run build:web      # builds the web app into web/dist (served by the API)
npm start              # http://localhost:4000
```

For development with hot reload, run `npm run dev:server` (port 4000) and `npm run dev:web` (port 5173, proxies `/api`).

The seed covers these scenarios: routine Go (batch-eligible); persistent possible seating gap (Visit + 45-min tracking
assessment); attachment possibly missing plus patient report; lost aligner (P2 triage); IPR due before the next stage
(Visit, and IPR is never inferred from photos); dark or blurry photos rejected by the real quality pipeline (automatic
retake request); overdue check-in; cracked aligner; low wear with poor fit (Hold); too early (Not yet); glare giving a
low-confidence Go; loose bracket on a fixed appliance; retention patient without AI consent.

Seed images are **synthetic illustrations** (`server/seed-assets`, generated by `server/scripts/generate-seed-images.mjs`)
and are watermarked as such. Seeded observations are stored as `source = seed_demo` and shown with a **"Demo data (not
model output)"** label. They are excluded from evaluation statistics.

### Turning on AI observations

1. Sign in as Dr. Okafor, then go to **Settings → AI providers → Add provider**.
2. Choose Anthropic, OpenAI, Google Gemini, or any OpenAI-compatible endpoint (Azure OpenAI, OpenRouter, self-hosted vLLM).
   Then set the model, a monthly budget and a per-call ceiling.
3. Open any check-in and click **Re-run analysis**. New patient check-ins are analysed automatically.

Keys are AES-256-GCM encrypted with the clinic's data key. They are never returned by the API, never logged, and never
sent to the Android app. You can also set `OMA_SEED_ANTHROPIC_KEY` before `npm run seed`.

### Patient app

Open a patient profile, click **Send app invite**, and enter the clinic code (`lumen-ortho`) and the activation code in the
Android app. See [`android/README.md`](android/README.md) for build instructions. The emulator talks to
`http://10.0.2.2:4000/api/v1/`.

## Architecture

```
 Android app ──HTTPS──▶ /api/v1/patient/*  ┐
 Clinic web  ──HTTPS──▶ /api/v1/*           ├─ Express API ─┬─ Tenant-scoped repositories (SQLite → Postgres)
 PMS / plan viewers ──▶ /api/v1/integrations/* (API keys)   ├─ Encrypted blob store (AES-256-GCM per tenant)
 Webhook receivers ◀── signed events (HMAC-SHA256)          ├─ Hash-chained audit log
                                                             └─ Services
   1. Quality service (deterministic, quality-v1.2)      ← same algorithm runs on-device in Kotlin
   2. Observation service (obs-prompt-v3) ─▶ Provider router ─▶ Anthropic | OpenAI | Gemini | OpenAI-compatible
   3. Rules engines: go/no-go (gonogo-v1) · triage (triage-v1) · appointments + chair time (appt-v1) · instr-parse-v1
   4. Evaluation: clinician confirm/dismiss/correct, missed findings, labelled cases, override tracking
```

These three services are separate, versioned and tested independently. Only the observation service calls an LLM.
